# Simple EC Site — 高桑商店

魚卵や海産物などの食品を扱う「高桑商店」を題材に制作した、Laravel製のECサイトです。

商品閲覧からカート・注文までの購入機能と、商品・注文・会員情報を扱う管理画面を備えています。

Web注文に加え、電話・FAX・店頭などで受け付けた注文も管理画面から登録できるようにし、小規模店舗での実際の運用を意識して開発しました。

現在は学習・試作段階です。送料・代引手数料の手動設定や配送情報の管理には対応していますが、送料の自動計算、在庫管理、メール通知などは未実装です。

## 制作の背景と目的

親族が運営する鮮魚・海産物販売サイトのリニューアルを想定して制作しました。

既存サイトは静的HTMLやPHPを中心とした構成で、商品情報の更新や注文管理などに改善の余地がありました。

そこで、Laravelとデータベースを利用し、商品情報や注文情報を一元管理できる仕組みを目指しました。

また、実際の店舗では高齢のお客様の利用も想定されるため、一般的なECサイトの機能を取り入れながらも、複雑な操作を避け、分かりやすい購入フローを意識しています。

### 開発で重視したこと

**1. 会員登録を必須にしない購入体験**

会員登録が購入の障壁にならないよう、ゲスト購入に対応しています。

一方、会員には住所・連絡先の保存や注文履歴の確認など、継続利用に便利な機能を用意しました。

**2. 自宅用・贈答用の両方に対応**

注文者とお届け先を分けて管理し、別住所への配送にも対応しています。

お届け先の指定に応じて、代金引換と銀行振込を使い分ける購入フローを採用しています。梱包や配送日時などの希望は、注文時の備考欄で受け付けます。

**3. 注文時点の情報を保持**

会員情報や商品情報が後から変更されても、過去の注文内容が変わらないよう、注文者情報・配送先情報・商品名・単価・税率などを注文データに保存しています。

**4. 店舗側の運用負担を軽減**

Web以外の受付経路にも対応し、管理画面から注文登録・内容修正・ステータス管理ができるようにしています。

送料・代引手数料は注文受付後に管理者が設定し、複数個口の送り状番号も注文に紐づけて管理します。

**5. スマートフォンでも利用しやすい画面**

購入者向け画面だけでなく、管理画面もレスポンシブ対応しています。

管理画面では、PC向けのテーブル表示とスマートフォン向けのカード表示を使い分けています。

- ゲストカートはセッションで保持
- 会員カートはデータベースで保持
- 一般会員としてログインすると、ゲストカートの商品を会員カートに統合
- 購入者向けカートの数量は、1商品につき最大50個（`config/cart.php` の `max_quantity` で変更可能）

#### 会員情報と注文情報

会員情報は注文フォームへの自動入力に利用しますが、注文時に入力した情報で会員プロフィールを更新することはありません。

注文情報は独立して保存されるため、会員情報を変更しても過去の注文には影響しません。

#### パンくずリスト

商品・カート・注文・お知らせなどの画面で、TOPから現在の画面までを階層的に表示します。現在地はリンクにせず、詳細画面では可能な範囲で商品名・注文番号・お知らせタイトルなどの固有名を表示します。商品カテゴリはパンくずの階層には含めず、商品詳細では「商品一覧」から商品名へ続く表示に統一しています。

#### FAX注文書の編集・出力

管理画面のFAX注文書管理では、左・中央・右の3列ごとに掲載商品とメッセージを編集できます。公開中の商品から選択し、注文書上の表示名を設定できます。各列の商品・メッセージは合計25件まで登録でき、商品選択リストは商品名順です。

変更は保存するまで公開されません。保存前の内容をプレビューで確認でき、保存後は購入者向けのPDFにも反映されます。PDFはブラウザーで表示し、印刷・保存できます。

管理画面はログイン認証と `is_admin` による権限確認で保護しています。

管理者アカウントは購入者向け注文画面からの注文を行えません。

会員情報は管理者による参照のみとし、編集機能は設けていません。顧客からの依頼による注文内容の変更は、会員プロフィールとは独立して管理します。

## ローカル環境のセットアップ

以下の手順は、PHP・Composer・Node.js・PostgreSQLを利用できる環境でのセットアップ例です。

コマンドはリポジトリ直下で実行します。

### 1. 必要な環境

- PHP 8.2以上と、Laravel・Composerの依存パッケージが要求するPHP拡張
- PostgreSQL接続用のPHP拡張（`pdo_pgsql`）
- TCPDFの依存関係が要求するPHP拡張（`ext-curl` など。詳細は `composer.lock` を参照）
- Composer 2系
- Node.js 22系とnpm
- PostgreSQLと、接続可能なデータベース・ユーザー

**データベースについて**

`.env.example` の初期設定はSQLiteですが、本アプリケーションではPostgreSQLを前提としています。

商品名・注文者氏名の検索では `ILIKE`、商品の並び替えでは `NULLS LAST` を使用しています。

他のデータベースを利用する場合は、これらのSQLとマイグレーションの互換性を確認してください。

```bash

```

シーダーで作成するデータは次のとおりです。

- 管理者・一般会員のサンプルアカウント

**注意：** `ProductSeeder` と `OrderSeeder` は実行のたびにデータを追加します。`php artisan db:seed` を繰り返すと商品・注文が重複するため、初回投入を前提に使用してください。

## 注文・入力の仕様

### 支払方法

購入者向けWeb注文では、お届け先の指定に応じて支払方法を自動決定します。購入者が支払方法を自由選択する方式ではありません。

| お届け先 | 支払方法 | 注文確定時のステータス |
| --- | --- | --- |
| 注文者と同じ | 代金引換（`cod`） | 受付（`received`） |
| 注文者と異なる | 銀行振込（`bank_transfer`） | 受付（`received`） |

管理画面からの手動登録では支払方法を選択でき、新規注文のステータスは同様に「受付」です。

管理者による支払方法の変更は、ステータスが「受付」の間のみ可能です。

### 注文ステータスと進行ルール

| ステータス | 保存値 | 意味 |
| --- | --- | --- |
| 受付 | `received` | 注文受付後、送料・手数料や内容を確認する段階 |
| 入金待ち | `awaiting_payment` | 銀行振込の入金を待つ段階 |
| 発送準備中 | `preparing` | 発送に向けた準備を進める段階 |
| 発送済 | `shipped` | 出荷処理を完了した段階 |
| キャンセル | `cancelled` | キャンセルされた注文 |

支払方法ごとの通常の進行は以下のとおりです。

- **代金引換：** 受付 → 発送準備中 → 発送済
- **銀行振込：** 受付 → 入金待ち → 発送準備中 → 発送済
- **キャンセル：** 発送済みになる前の注文は管理者がキャンセル可能

送料・代引手数料の確定など、各段階で必要な条件を満たさなければ次のステータスへ進めません。

特に「発送準備中」から「発送済」へ進めるには、**配送個口が1件以上登録され、すべての個口に送り状番号が入力されていること**が必要です。

### 注文情報の編集制限

| 注文ステータス | 注文内容の編集 |
| --- | --- |
| 受付 | 編集可能 |
| 入金待ち | 警告を表示したうえで編集可能 |
| 発送準備中 | 警告を表示したうえで編集可能 |
| 発送済 | 編集不可 |
| キャンセル | 編集不可 |

注文内容には、注文明細や注文者・お届け先、送料・手数料などが含まれます。管理メモは注文ステータスにかかわらず編集できます。

配送・送り状情報は別の運用ルールとし、**発送済みでも修正可能**です。キャンセル済み注文では編集できません。

### 送料・代引手数料と注文金額

注文金額は、商品代金と送料・手数料を分けて管理します。
商品価格・注文明細の単価・送料・代引手数料は、すべて税込金額として扱います。

- `orders.total_amount`：商品代金の合計（送料・手数料は含めない）
- `orders.shipping_fee`：注文単位の送料。複数個口の場合も合算額を登録
- `orders.cod_fee`：代引手数料。代金引換以外の支払方法では、費用更新時に0円として保存
- **最終的なお支払い総額：** 商品代金合計 ＋ 送料 ＋（代金引換の場合は代引手数料）

送料・代引手数料は管理者が手動で設定します。各金額は `null` を「未確定」、`0` を「確定済み・無料」として区別します。

購入者向けの注文確認画面では、送料・該当する手数料が注文受付後に加算されることを案内し、注文確定前にチェックボックスで同意を取得します。

購入者向けの注文詳細画面では、必要な金額が確定するまで支払総額を「未確定」と表示します。

### 税率の選択と消費税内訳

#### 税率の設定・保存

対応する税率は `config/shop.php` の `tax` に定義しています。

| 設定キー | 現在の値 | 用途 |
| --- | --- | --- |
| `tax.rates` | 8%：軽減税率、10%：標準税率 | 商品・注文明細の選択肢と入力検証 |
| `tax.default_rate` | 8 | 商品・自由入力明細の新規入力時の初期選択 |
| `tax.shipping_rate` | 10 | 送料・代引手数料に適用する税率 |

管理画面の商品登録・編集では、税込価格と消費税率を設定します。管理画面の注文登録・明細編集でも、明細ごとに税率を選択できます。

商品選択時には、商品マスタの商品名・税込単価・税率を明細にコピーします。その後、商品名・単価・税率のいずれかを変更すると商品連携を解除し、自由入力明細として扱います。

Web注文では商品マスタの税率を `order_items.tax_rate` に保存します。注文確認時の商品・価格・数量・税率をスナップショットに記録し、確定時にいずれかが変わっていた場合は再確認を求めます。注文後に商品マスタの税率を変更しても、保存済み明細の税率は変わりません。

#### 計算方法と再計算のタイミング

消費税の計算は `app/Services/TaxCalculator.php` にまとめています。

1. 明細の小計（税込単価 × 数量）を税率別に合算する
2. 送料・代引手数料を、設定された費用の税率（現在10%）の対象額に加算する
3. 税率別の対象額から、`内消費税 = 税込対象額 × 税率 ÷ (100 + 税率)` を計算する
4. 税率ごとに1回だけ、1円未満の端数を切り捨てる

例えば、8%対象の商品合計が税込2,700円、10%対象の送料・代引手数料が税込1,430円の場合、内消費税はそれぞれ200円・130円です。内税額は税込金額に含まれるため、支払総額に再加算しません。

値引きは負の単価を持つ明細で入力でき、選択した税率の対象額から差し引きます。注文全体の合計に加え、税率別の対象額がマイナスになる登録・更新もエラーにします。対象額が0円の税率は集計を保存しません。

Web注文・管理画面の注文登録時に集計を作成し、管理画面での注文明細・送料・代引手数料・支払方法の更新時に再計算します。未確定の送料・手数料（`null`）は計算上0円として扱い、設定後に内訳へ反映します。

税率別集計は `order_tax_summaries` に、注文・税率ごとに1件保存します。

| カラム | 内容 |
| --- | --- |
| `tax_rate` | 税率（%） |
| `tax_included_amount` | 税率別の税込対象額（該当する送料・手数料を含む） |
| `tax_amount` | 税率別の内消費税額 |

注文・明細・税率別集計の登録・更新は、同じDBトランザクション内で行います。

#### 表示する画面

会員向け注文詳細と管理画面の注文詳細に、明細ごとの税率、および税率別の「税込対象額」「内消費税」を表示します。納品書PDFにも保存済みの税率別税額を記載します。集計データがない注文では、画面・納品書ともに消費税内訳を表示しません。

注文確認・注文完了画面は商品代金合計と送料・手数料の案内を表示し、税率別内訳は表示しません。送料・手数料が未確定の間は、注文詳細の内訳もその費用を含まない段階の集計です。

### 納品書PDF

管理画面の注文詳細に表示される「納品書を発行」から、A4縦のPDFを別タブで開けます。ブラウザのPDFビューアーから印刷・保存できます。出力処理は `app/Services/DeliverySlipPdf.php` にまとめています。

#### 発行条件

`Order::canIssueDeliverySlip()` で、次の条件をすべて満たすか確認します。

- 注文ステータスが「入金待ち」「発送準備中」「発送済」のいずれか
- 送料が確定済み（`shipping_fee` が `null` 以外。0円も発行可能）
- 代金引換の場合は、代引手数料も確定済み（`cod_fee` が `null` 以外）

「受付」「キャンセル」の注文や、必要な費用が未確定の注文には発行ボタンを表示しません。URLへ直接アクセスした場合も同じ条件で検証し、条件を満たさなければ403を返します。管理者向けルートとして保護しており、購入者向けの発行機能はありません。

#### 記載内容と出力方式

- 注文日、お届け先、請求先（注文者情報）、発送元の店舗情報
- 決済方法、商品名、税込単価、数量、税込小計
- 商品合計・送料・代引手数料（代金引換の場合）・支払合計
- 保存済みの税率別消費税額。税率8%の明細には「※」と軽減税率対象の注記
- 店舗ロゴ（`public/images/logo.png` が存在する場合）

注文・明細・税率別集計の保存データから、その都度PDFを生成して返します。PDFファイルの保存や発行履歴の記録は行いません。保存時の日本語ファイル名は、注文IDを8桁にゼロ埋めした `納品書_00000001.pdf` 形式です。レスポンスには互換用の英字ファイル名 `delivery-slip-1.pdf` も設定しています。

発送元の名称・住所・電話・メールは、フッターと共通の `config/company.php` を参照します。PDFのロゴ画像は `company.logo` のSVGとは別に、上記のPNGを直接参照します。
(TCPDFとSVGの相性がよくないため)

商品明細が10行未満の場合は空行を補います。商品合計・送料・手数料消費税のグループが分離されないように改ページを行います。長い商品名については明細の高さを変えて改行表示します。住所・メールアドレスなどが長い場合も適切に改行を行い、それぞれの文字が重ならないようにしています。

配送会社は現時点では**ヤマト運輸のみ**を想定しています。

- 注文に紐づく配送個口を `order_shippings` テーブルで管理
- 1注文に複数の個口を登録可能
- 個口ごとに送り状番号（`tracking_number`）を保存
- 管理画面で個口・送り状番号の追加、変更、削除が可能
- 発送済みの注文は、会員向け注文詳細画面に個口ごとの送り状番号と配送状況の確認リンクを表示

現時点では送り状番号を管理者が入力する方式です。ヤマト運輸B2クラウドとのCSV連携は未実装です。

### 注文時の備考欄と管理メモ

購入者は注文時に、包装・梱包方法、お届け日時、複数箱への分割などの希望を**任意の備考欄**に入力できます。

- `orders.customer_note` に保存（任意、最大1,000文字）
- 注文内容確認画面、注文完了画面、会員向け注文詳細画面に表示
- 管理画面の注文詳細では、注文商品の近くに強調表示
- 注文確定後は、購入者・管理者ともに備考欄を編集できない
- 顧客の希望が必ず実現できることを保証するものではない

一方、`orders.memo` は管理者が社内の対応状況などを記録するための**管理メモ**であり、顧客の備考とは別に扱います。

**## 本番環境へのデプロイ手順（確認用チェックリスト）**

以下はホスティングサービスに依存しない基本手順です。実際の公開方法、Webサーバーの設定、利用可能なコマンドは配置先の環境に合わせて調整してください。**初回公開と既存環境の更新を区別**し、作業前にデータベースとアップロード画像をバックアップします。

**### 1. 公開前の準備**

- 本番サーバーのPHPバージョン・必要な拡張（特に `pdo_pgsql`）・Composer実行可否を確認する
- PostgreSQLへの接続方法、Webサーバーのドキュメントルートを確認する。Laravelの公開先は原則 `public/` とし、`.env` やアプリケーション本体をWebから直接参照できない構成にする
- `composer.lock` と `package-lock.json` を含むデプロイ対象のコミットを確定する
- 本番用データベースと接続ユーザーを作成し、権限を必要最小限にする
- `storage/` と `bootstrap/cache/` の書き込み権限、画像保存先の永続性、HTTPS証明書を確認する
- 本番公開前にテストと注文フローの動作確認を行う。テストに既知の失敗がある場合は原因を解消するか、公開判断時に明示的に扱う

**### 2. 本番用 `.env` の設定**

`.env` は本番サーバー上で管理し、Gitへコミットしない。以下は**設定項目の例**であり、実際の秘密情報は記載しない。

```dotenv
APP_NAME="高桑商店"
APP_ENV=production
APP_DEBUG=false
APP_URL=https://example.com
APP_KEY=base64:（本番用に生成したキー）

DB_CONNECTION=pgsql
DB_HOST=（本番DBホスト）
DB_PORT=5432
DB_DATABASE=（本番DB名）
DB_USERNAME=（本番DBユーザー）
DB_PASSWORD=（本番DBパスワード）

SESSION_DRIVER=database
CACHE_STORE=database
QUEUE_CONNECTION=database
MAIL_MAILER=log
```

- `APP_ENV=production` は本番環境であることをLaravelへ伝える。環境条件分岐や一部のArtisanコマンドの挙動に影響する
- `APP_DEBUG=false` は必須。想定外の例外の詳細を利用者へ表示しない。例外の記録先は `LOG_CHANNEL` などのログ設定によって決まる
- `APP_URL` は実際のHTTPS公開URLにする。Webサーバー側でもHTTPSを強制し、リバースプロキシを使う場合は信頼設定を確認する
- `APP_KEY` は初回構築時に安全に生成し、**運用開始後は不用意に再生成しない**。既存の暗号化データやセッションに影響する
- DB接続情報、メール認証情報などは秘密情報として保護する。`APP_DEBUG=false` でもログへの機密情報出力には注意する
- `MAIL_MAILER=log` は実メールを送信しない暫定設定。注文通知やパスワード再設定メールを実運用する前に送信方式と到達性を検証し、適切な設定へ変更する

```bash
php artisan optimize
```

- `.env` を用意してからマイグレーションを実行する。`migrate --force` は本番環境の確認プロンプトを省略するため、対象DBとバックアップを必ず確認する
- **本番では `migrate:fresh` や `migrate --seed` を安易に実行しない**。開発用の固定アカウント・サンプル注文を公開環境へ投入しない
- 画像は `storage/app/public/products` に保存するため、`public/storage` のシンボリックリンクと画像ファイルの継続保存を確認する
- キャッシュ生成に失敗する場合はエラー原因を解消し、設定変更後はキャッシュを再生成する
- キューを利用する処理を本番で有効にする場合は、適切なワーカー起動・監視方法を別途設定する

**### 4. 公開後の動作確認**

- HTTPSでトップページ、商品一覧、商品詳細、画像が表示される
- 会員登録・ログイン・ログアウト・パスワード再設定の導線を確認する（メール送信が未整備の場合は本番利用開始前に対応する）
- ゲストと会員のカート操作、注文確認・確定、注文履歴の表示を確認する
- 管理画面への権限制御、商品登録・編集、注文登録・編集、配送情報を確認する
- 税率8%・10%混在の注文、送料・代引手数料の確定、支払方法変更後の税率別内訳を確認する
- 納品書の発行条件、管理者以外のアクセス制限、日本語・ロゴ・軽減税率注記・税額・印刷レイアウトを確認する。PDF用フォントを含め、`storage/fonts/tcpdf/` に必要なファイルが配置されていることを確認する
- 意図的に500エラーを発生させる場合は**非公開の検証環境**で実施し、画面に内部情報が出ず、設定したログ出力先に詳細が残ることを確認する
- `storage/logs/` または設定済みのログ出力先を確認し、例外・警告が継続していないか確認する

**### 5. 更新・障害対応時の注意**

- 更新前にDBとアップロード画像をバックアップし、戻せるソースのバージョンを記録する
- 更新時は依存関係・ビルド成果物・マイグレーションの変更有無を確認する。スキーマ変更がある場合はロールバック可能性も事前に検討する
- `.env` の設定を変更したら設定キャッシュを再生成する。`APP_DEBUG=true` を本番で常用しない
- 画面に500エラーが出たら、利用者には一般的なエラー画面を表示し、運用者はLaravelログ・Webサーバーログ・DB接続・権限・キャッシュを調査する
- メール送信機能は未実装。公開前に必要な通知機能の実装・送信テスト・運用手順を別途整備する


## 現時点の対応範囲と今後の課題

本アプリケーションは学習・試作段階であり、以下の機能や運用対応は未実装、または今後の改善対象としています。

| 項目 | 現状 |
| --- | --- |
| 送料・代引手数料 | 注文単位の手動設定に対応。自動計算は未実装 |
| 配送・送り状管理 | 複数個口と追跡番号の管理に対応。B2クラウドCSV連携は未実装 |
| 納品書 | 管理者向けPDF出力に対応。発行履歴の管理は未対応 |
| 外部決済連携 | 未実装。支払方法の記録のみ対応 |
| 入金の自動確認 | 未実装。管理者が確認してステータスを進行 |
| 在庫管理・在庫引当 | 未実装 |
| 注文確認・発送通知メール | 未実装。公開時にメール通知を整備予定 |
| メールアドレス認証 | 画面・ルートはあるが、現在は認証を必須としていない |
| パスワード再設定メール | 開発環境の `MAIL_MAILER=log` ではログに出力 |
| 自動テスト | カート・注文・商品管理・設定値の回帰テストあり。税計算テストは設定初期化の修正が必要。ブラウザ操作テストは未対応 |
| 店舗情報・案内ページ | 店舗情報は `config/company.php` に集約。案内ページは一部仮置き |

本番運用に向けては、メール送信設定、店舗情報・案内ページの整備、入力値の正規化、セキュリティ対策、テストの追加などを進める予定です。

## 制作について

本プロジェクトは、Laravelの学習を通じて習得した知識を活用し、実際の店舗運用を想定して制作したアプリケーションです。
