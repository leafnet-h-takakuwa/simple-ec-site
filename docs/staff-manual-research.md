# 店舗スタッフ向け操作マニュアル：事前調査と構成案

## この資料について

- 対象：ITやパソコン操作に詳しくない店舗スタッフ
- 目的：実装済みの管理画面機能を整理し、次段階で作成する操作マニュアルの構成・確認事項・画面撮影計画をまとめる
- 調査方法：README、ルート、Controller、Model、Blade、入力検証を照合
- 制限：画面を実際に起動して操作した確認や、運用担当者への聞き取りはしていない。画面画像も作成していない。
- 既存のアプリケーションコードは変更していない。

「確認できた事実」はソースコード上の実装を示す。店舗の実際の運用ルールや本番環境の設定を意味するものではない。

## 1. 調査結果：確認できた事実

### 1-1. 管理画面への入口と機能

管理画面は `/admin` 以下にあり、ログイン済みで管理者権限のあるアカウントが必要。管理者でないアカウントで開くとアクセス拒否になる。画面の管理メニューには、ダッシュボード、注文管理、商品管理、FAX注文書管理、お知らせ管理、顧客台帳、WEB会員管理がある。

| 画面 | URL | 確認できた操作 |
| --- | --- | --- |
| ダッシュボード | `/admin` | 対応中・直近7日間・全注文・発送済みの件数、商品最終更新日時を確認。件数から注文一覧へ移動 |
| 注文管理 | `/admin/orders` | 注文検索、一覧確認、注文登録、詳細表示 |
| 注文登録 | `/admin/orders/create` | Web以外の注文を含む手動登録 |
| 商品管理 | `/admin/products` | 商品検索、登録、編集、公開設定、削除 |
| 顧客台帳 | `/admin/customers` | 顧客の検索、登録、詳細、編集、削除 |
| WEB会員管理 | `/admin/users` | 会員一覧、会員詳細、会員ごとの注文履歴を閲覧 |
| お知らせ管理 | `/admin/notices` | お知らせの登録、編集、削除、公開設定 |
| FAX注文書管理 | `/admin/fax-order-form` | FAX注文書の掲載商品・表示名・メッセージを編集、プレビュー、保存 |

主な根拠：[web.php](../routes/web.php)、[EnsureUserIsAdmin.php](../app/Http/Middleware/EnsureUserIsAdmin.php)、[layouts/admin.blade.php](../resources/views/layouts/admin.blade.php)

### 1-2. 商品の登録・編集・公開

- 商品一覧では商品名の部分一致と「すべて／公開中／非公開」で検索でき、新しい登録順に表示される。
- 登録・編集項目は、商品名、分類、内容量、税込価格、消費税率、公開状態、定番商品、商品説明、画像。
- 商品名・分類・内容量・価格・税率・公開状態は必須。価格は0円以上の整数。画像は任意で、JPEG・PNG・WebP、設定上限5MB。
- 新規登録画面の初期状態は「公開中」、消費税率は設定された初期値（README上は8%）。画面で必ず確認してから登録する。
- 保存後は商品一覧に戻り、編集の保存後は商品編集画面に成功メッセージが表示される。
- 画像の編集では、新しい画像を選ぶと差し替えが優先される。「現在の画像を削除する」を選んで保存すると画像なしにできる。
- 削除は論理削除で、商品一覧・購入者側の商品表示から除外される。過去の注文履歴は残る。管理画面に復元操作は見当たらない。
- 公開／非公開を切り替えると、購入者側の商品一覧への表示に影響する。注文中の商品が非公開になった場合の既存カート等への影響は、マニュアル化前に運用側と確認する。

主な根拠：[ProductController.php](../app/Http/Controllers/Admin/ProductController.php)、[ProductRequest.php](../app/Http/Requests/Admin/ProductRequest.php)、[create.blade.php](../resources/views/admin/products/create.blade.php)、[edit.blade.php](../resources/views/admin/products/edit.blade.php)、[index.blade.php](../resources/views/admin/products/index.blade.php)

### 1-3. 注文の検索・確認とWeb注文の管理

- 注文一覧は新しい注文から表示。検索項目は注文番号（完全一致）、注文者氏名（部分一致）、注文日の開始日・終了日、ステータス。検索条件はページ移動後も保持される。
- ステータスの「対応中」は、受付・入金待ち・発送準備中を指す。
- 一覧には注文日、8桁表示の注文番号、受付経路、注文者、商品代金合計、ステータスが表示される。各注文の「詳細」から内容を確認する。
- Web注文と電話・FAX・店頭等の注文は同じ注文管理一覧・詳細で扱う。注文詳細に受付経路が表示され、Web注文専用の管理画面はない。
- 注文詳細には注文商品と内容量、数量、税込単価、小計、顧客からの要望、支払方法、送料・手数料、税率別内訳、配送・送り状情報、注文者・お届け先、管理メモ、対応履歴がある。
- 注文時の商品名・価格・税率・注文者・お届け先等は注文データに保存される。後から商品マスタや会員プロフィールを変更しても、過去注文の情報はその変更で置き換わらない。
- 顧客の備考欄（注文時の要望）は注文確定後に編集できない。社内用の管理メモは別項目で、注文ステータスに関わらず更新できる。詳細画面では入力欄からフォーカスが外れると自動保存し、保存状態が表示される。

主な根拠：[OrderController.php](../app/Http/Controllers/Admin/OrderController.php)、[Order.php](../app/Models/Order.php)、[orders/index.blade.php](../resources/views/admin/orders/index.blade.php)、[orders/show.blade.php](../resources/views/admin/orders/show.blade.php)

### 1-4. 電話・FAX・店頭等の注文の手動登録

1. 管理メニューの「注文管理」から「注文を登録」を開く。
2. 「注文経路」を選ぶ（Web・電話・FAX・店頭・その他）。
3. 商品明細を登録する。「商品を選択」から商品を選ぶか、商品名・内容量・単価・数量・税率を入力する。商品マスタにない明細も登録できる。明細は1件以上必要。
4. 注文者情報とお届け先情報を入力する。顧客台帳から転記するか、「注文者情報をコピー」を利用できる。注文者のメールアドレスは任意。
5. 支払方法を選び、必要なら管理メモを入力する。
6. 「注文を登録」を押すと登録され、注文詳細へ移動する。新規注文のステータスは「受付」。詳細画面で受付経路、明細、注文者・お届け先、商品代金合計、管理メモを確認する。
- 登録操作に確認画面はなく、送信時に注文が作成される。誤登録時の訂正・キャンセル方法をマニュアルで目立つように案内する必要がある。
- 新規注文登録後は注文受付メールの処理が呼ばれる。実際に配信されるかはメール設定に依存する。
- 注文者・お届け先情報は顧客台帳にも反映される。同じ人物と判定された既存顧客の住所・連絡先・メモは自動で上書きされず、利用区分のみ更新される。
- 合計金額がマイナスになる注文は登録できない。値引き明細は負の単価で入力できるが、税率別対象額がマイナスになる場合もエラーになる。通常操作手順では値引きルールの確認が必要。
- 新規登録フォームには送料・代引手数料の入力欄がない。注文作成後、注文詳細から別途設定する。

主な根拠：[OrderController.php](../app/Http/Controllers/Admin/OrderController.php)、[orders/create.blade.php](../resources/views/admin/orders/create.blade.php)、[CustomerService.php](../app/Services/CustomerService.php)、[OrderSource.php](../app/Enums/OrderSource.php)

### 1-5. 注文内容・注文者・お届け先・支払方法の編集

- 注文詳細の「明細を編集」から、商品明細の追加・修正・削除ができる。商品名、内容量、税込単価、数量、税率を確認し、保存後に注文合計と税額内訳が再計算される。
- 注文詳細の「お客様情報を編集」から、注文者とお届け先の氏名、郵便番号、住所、電話番号、注文者メールアドレスを編集できる。お届け先欄の「注文者情報をコピー」も使える。
- 「お客様からのご要望」は読み取り専用。注文後に変更したい希望は、顧客への確認・社内手順を決めてから、必要に応じて管理メモ等に記録する。
- 支払方法はステータスが「受付」の間だけ変更できる。支払方法を切り替えると代引手数料は、代引へ変更時に未確定、代引以外へ変更時に0円へ更新される。
- 「受付」は通常編集可能。「入金待ち」「発送準備中」は編集できるが、金額案内済みの可能性を知らせる警告が表示される。「発送済」「キャンセル」は注文内容・注文者情報を編集できない。
- 「変更を保存」後は注文詳細へ戻り、成功表示と更新後の値を確認する。保存前後で金額・届け先等が変わるため、変更前に注文内容と顧客への案内状況を照合する。

主な根拠：[OrderController.php](../app/Http/Controllers/Admin/OrderController.php)、[orders/edit-items.blade.php](../resources/views/admin/orders/edit-items.blade.php)、[orders/edit-customer.blade.php](../resources/views/admin/orders/edit-customer.blade.php)、[order-edit-warning.blade.php](../resources/views/components/admin/order-edit-warning.blade.php)

### 1-6. 送料・代引手数料、ステータス、配送伝票

**送料・代引手数料**

- 注文詳細の「送料・手数料を編集」から注文単位で税込金額を入力する。複数個口でも送料欄は注文合計額。
- 空欄は「未確定」、0円は「確定済み・無料」、正の整数は確定金額。送料・手数料の自動計算はない。
- 代金引換以外では代引手数料欄を表示せず、更新時は0円扱い。
- 「受付」から次へ進むには送料が確定している必要がある。代引の場合は代引手数料も確定している必要がある。0円を入力すれば「確定済み」となる。
- 送料・手数料は税込として扱い、注文の総額・税率別内訳に反映される。

**ステータス**

| 現在の状態／条件 | 次の状態 |
| --- | --- |
| 受付・銀行振込 | 入金待ち（送料が確定済みであること） |
| 受付・代金引換 | 発送準備中（送料・代引手数料が確定済みであること） |
| 受付・店頭支払 | 発送準備中（送料が確定済みであること） |
| 入金待ち | 発送準備中（画面に入金確認を促す注意が表示される） |
| 発送準備中 | 発送済（全個口の送り状番号が登録済みであること） |
| 発送済み前 | キャンセル可能 |

ステータス更新のたびに、お客様への連絡方法（メール、電話、FAX、対面、連絡不要）を選ぶ。メールを選んだ場合、対象の変更・注文者メールアドレス等が条件を満たせば自動送信処理を行う。連絡メモも記録でき、注文詳細に対応履歴が残る。発送済み・キャンセル後はステータス変更できない。

**個口・送り状番号**

- 注文詳細の「送り状情報を編集」から、個口ごとに送り状番号を追加・変更・削除する。配送会社の表示はヤマト運輸。番号の入力上限は20文字。
- 保存後、詳細画面で個口番号を確認する。番号が入ると、配送状況の確認リンクが表示される。
- 発送準備中から発送済みにするには、個口が1件以上あり、すべての個口に送り状番号が必要。空欄の個口が残ると発送済みにできない。
- 発送済み後も送り状番号の訂正は可能。キャンセル済みは配送情報を編集できない。個口行を削除して保存するとその配送レコードが削除されるため、削除操作は慎重に行う。
- B2クラウドとのCSV連携・送り状番号の自動取込は未実装。

主な根拠：[OrderController.php](../app/Http/Controllers/Admin/OrderController.php)、[OrderStatus.php](../app/Enums/OrderStatus.php)、[orders/show.blade.php](../resources/views/admin/orders/show.blade.php)、[Order.php](../app/Models/Order.php)

### 1-7. 会員情報、顧客台帳、その他

- **WEB会員管理**：会員一覧と詳細を閲覧し、会員ごとの注文履歴へ移動できる。退会済み会員も一覧・詳細に含まれる。管理画面から会員プロフィールを編集する機能はない。
- **顧客台帳**：WEB会員情報とは別のデータ。氏名、電話、郵便番号、住所、任意メール、利用区分（注文者／配送先）、任意メモを登録・編集できる。検索キーワードは氏名・郵便番号・住所・電話・メール・メモを対象とする。注文者または配送先の少なくとも一方を指定する。削除は論理削除で、画面に復元機能は見当たらない。
- **お知らせ管理**：タイトル、本文、公開日、公開状態を登録・編集。公開日が未来なら予約表示。本文編集はリッチテキストで、保存時に許可対象のHTMLへ制限される。削除すると購入者側に表示されなくなる。
- **FAX注文書管理**：左・中央・右の各列に商品・メッセージを配置。各列合計25件まで。公開商品から選び、注文書表示名を設定する。保存前プレビューを確認でき、変更は保存するまで購入者向けPDFへ反映されない。
- **納品書**：注文詳細からPDF発行。ステータスが入金待ち・発送準備中・発送済で、送料が確定済み（0円含む）であることが必要。代引では代引手数料も確定済みであること。PDFは保存・印刷できるが、発行履歴は記録されない。
- **ダッシュボード**：各件数から条件付き注文一覧へ移動できる。商品情報の最終更新日時も表示。
- **在庫管理・外部決済・入金自動確認・送料自動計算**は未実装とREADMEに記載。

主な根拠：[UserController.php](../app/Http/Controllers/Admin/UserController.php)、[CustomerController.php](../app/Http/Controllers/Admin/CustomerController.php)、[NoticeController.php](../app/Http/Controllers/Admin/NoticeController.php)、[FaxOrderFormController.php](../app/Http/Controllers/Admin/FaxOrderFormController.php)、[DeliverySlipPdf.php](../app/Services/DeliverySlipPdf.php)、[README.md](../README.md)

## 2. 未確認事項・運用担当者への確認事項

コードで定まらない事項は、マニュアルに断定形で記載しない。

1. **ログイン方法**：本番URL、スタッフ用アカウントの発行・権限付与、パスワード紛失時の連絡先。READMEのサンプルアカウントは開発用であり、店舗のログイン情報として使わない。
2. **送料・代引手数料**：地域・サイズ・温度帯・個口数別の料金表、誰が金額を確認・入力するか、無料条件、入力後に顧客へ案内する手順。
3. **注文の進め方**：銀行振込の入金確認担当・確認方法、店頭支払注文の実際の進行、各ステータスを変更するタイミングと担当。
4. **顧客連絡**：メールを使う条件、電話・FAX・対面での連絡記録の書き方、連絡不要にできる条件、誤ったメールアドレス等の対応。
5. **配送**：ヤマト運輸以外を使う場合の扱い、個口数を決めるルール、番号を取得するタイミング、発送後の番号訂正・配送事故時の連絡先。
6. **誤操作・取消**：商品・顧客・お知らせの削除後に復元できるか、誤った注文登録・金額変更・キャンセル時に誰へ報告するか。画面上には復元機能が見当たらないため、管理者確認手順を決める。
7. **公開情報**：商品説明・画像・価格・税率の承認者、公開／非公開の切替タイミング、予約お知らせの公開確認担当。
8. **メール配信環境**：本番のメール配信設定・配信失敗時の確認手段。コードには送信処理があるが、実際の配信状況は環境設定の確認が必要。
9. **個人情報の扱い**：会員・注文情報を閲覧できるスタッフの範囲、画面撮影・印刷物の保管ルール。
10. **画面の実環境確認**：PC／スマートフォンそれぞれの表示、メニューの位置、エラー時の表示を実機で確認する。ソース確認のみで実際の操作確認はしていない。

## 3. マニュアルの構成案

専門用語を避け、画面に表示されるボタン名を引用し、1つの作業を短い手順に分ける。

1. **はじめに**：対象スタッフ、管理画面でできること、個人情報の取扱い、困ったときの連絡先
2. **ログインと画面の見方**：本番URL、ログイン、管理メニュー、戻る操作、保存成功・入力エラーの見分け方
3. **毎日の注文確認**：ダッシュボード → 注文一覧 → 条件検索 → 注文詳細で確認する項目
4. **商品を登録・直す**：商品登録、価格・税率・画像の確認、公開／非公開、保存後の表示確認、削除前の注意
5. **Web注文に対応する**：Web注文の見分け方、顧客希望・連絡先・支払方法・送料の確認
6. **電話・FAX・店頭注文を登録する**：受付経路、商品明細、顧客台帳の転記、注文者・届け先、支払方法、登録後の確認
7. **注文内容・お客様情報を変更する**：編集可能な状態、注意表示、変更前の顧客確認、保存後の金額・届け先確認
8. **送料・代引手数料を入力する**：料金表確認、未確定と0円の違い、総額確認、顧客への案内
9. **注文を次の状態へ進める／キャンセルする**：支払方法別の流れ、入金確認、連絡方法・対応メモ、キャンセルの影響
10. **送り状番号・複数口を登録する**：口数追加、各番号確認、発送済みにする前のチェック、発送後の訂正
11. **会員・顧客台帳を確認する**：WEB会員と顧客台帳の違い、検索、編集可能範囲
12. **その他の管理機能**：お知らせ、FAX注文書、納品書PDF
13. **よくある困りごとと確認事項**：保存できない、次の状態へ進めない、番号不足、誤登録、メールが届かない
14. **用語集**：「受付」「入金待ち」「発送準備中」「個口」「送り状番号」「未確定」など

## 4. 画面キャプチャ候補

実画面から撮影し、画像は捏造しない。顧客名・住所・電話・メール・注文番号などは、撮影用の架空データを使うか、判読できないように加工する。操作手順で使うボタンや値は隠さない。

| ID | 撮影対象・画面 | 必要な表示状態 | 写す項目・説明に使う箇所 |
