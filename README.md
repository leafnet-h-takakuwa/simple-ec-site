# Simple EC Site — 高桑商店

魚卵や海産物などの食品を扱う「高桑商店」を題材に制作した、Laravel製のECサイトです。

商品閲覧からカート・注文までの購入機能と、商品・注文・会員情報を扱う管理画面を備えています。

Web注文に加え、電話・FAX・店頭などで受け付けた注文も管理画面から登録できるようにし、小規模店舗での実際の運用を意識して開発しました。

現在は学習・試作段階です。送料・代引手数料の手動設定や配送情報の管理には対応していますが、送料の自動計算、在庫管理、メール通知などは未実装です。

## 制作の背景と目的

親族が運営する鮮魚・海産物販売サイトのリニューアルを想定して制作しました。

既存サイトは静的HTMLやPHPを中心とした構成で、商品情報の更新や注文管理などに改善の余地がありました。

そこで、Laravelとデータベースを利用し、商品情報や注文情報を一元管理できる仕組みを目指しました。

また、実際の店舗では高齢のお客様の利用も想定されるため、一般的なECサイトの機能を取り入れながらも、複雑な操作を避け、分かりやすい購入フローを意識しています。

### 開発で重視したこと

**1. 会員登録を必須にしない購入体験**

会員登録が購入の障壁にならないよう、ゲスト購入に対応しています。

一方、会員には住所・連絡先の保存や注文履歴の確認など、継続利用に便利な機能を用意しました。

**2. 自宅用・贈答用の両方に対応**

注文者とお届け先を分けて管理し、別住所への配送にも対応しています。

お届け先の指定に応じて、代金引換と銀行振込を使い分ける購入フローを採用しています。梱包や配送日時などの希望は、注文時の備考欄で受け付けます。

**3. 注文時点の情報を保持**

会員情報や商品情報が後から変更されても、過去の注文内容が変わらないよう、注文者情報・配送先情報・商品名・単価などを注文データに保存しています。

**4. 店舗側の運用負担を軽減**

Web以外の受付経路にも対応し、管理画面から注文登録・内容修正・ステータス管理ができるようにしています。

送料・代引手数料は注文受付後に管理者が設定し、複数個口の送り状番号も注文に紐づけて管理します。

**5. スマートフォンでも利用しやすい画面**

購入者向け画面だけでなく、管理画面もレスポンシブ対応しています。

管理画面では、PC向けのテーブル表示とスマートフォン向けのカード表示を使い分けています。

#### カートの仕様

- ゲストカートはセッションで保持
- 会員カートはデータベースで保持
- 一般会員としてログインすると、ゲストカートの商品を会員カートに統合
- 購入者向けカートの数量は、1商品につき最大10個

#### 会員情報と注文情報

会員情報は注文フォームへの自動入力に利用しますが、注文時に入力した情報で会員プロフィールを更新することはありません。

注文情報は独立して保存されるため、会員情報を変更しても過去の注文には影響しません。

| 機能 | 内容 |
| --- | --- |
| ダッシュボード | 進行中・直近7日間・全件・発送済みの注文件数、商品の最終更新日時を表示 |
| 商品管理 | 一覧・検索・登録・編集・削除、画像の登録・変更・削除 |
| 商品の表示設定 | 公開／非公開、定番商品の設定 |
| 注文検索 | 注文番号・注文者氏名・注文日・ステータスによる絞り込み |
| 手動注文登録 | Web・電話・FAX・店頭・その他の受付経路を選択して登録 |
| 注文明細編集 | 商品・単価・数量の変更、明細の追加・削除、商品代金合計の再計算 |
| 自由入力の明細 | 商品マスタにない商品名・金額を入力して登録 |
| 注文情報の変更 | 注文者・お届け先・支払方法・ステータスの更新（状態に応じた制限あり） |
| 送料・代引手数料 | 注文ごとに金額を手動設定。未確定・0円・金額ありを区別 |
| 配送・送り状情報 | 注文ごとに複数個口を登録し、送り状番号を追加・変更・削除 |

| お客様からのご要望 | 注文時の備考を管理画面で強調表示。編集不可 |
| 管理メモ | 顧客の備考とは別に、管理者が対応内容などを記録・更新 |
| 会員情報の閲覧 | 会員一覧・詳細、会員ごとの注文履歴を表示 |

管理画面はログイン認証と `is_admin` による権限確認で保護しています。

管理者アカウントは購入者向け注文画面からの注文を行えません。

会員情報は管理者による参照のみとし、編集機能は設けていません。顧客からの依頼による注文内容の変更は、会員プロフィールとは独立して管理します。

以下の手順は、PHP・Composer・Node.js・PostgreSQLを利用できる環境でのセットアップ例です。

- PHP 8.2以上と、Laravel・Composerの依存パッケージが要求するPHP拡張

## 注文・入力の仕様

### 支払方法

購入者向けWeb注文では、お届け先の指定に応じて支払方法を自動決定します。購入者が支払方法を自由選択する方式ではありません。

| お届け先 | 支払方法 | 注文確定時のステータス |
| --- | --- | --- |
| 注文者と同じ | 代金引換（`cod`） | 受付（`received`） |
| 注文者と異なる | 銀行振込（`bank_transfer`） | 受付（`received`） |

管理画面からの手動登録では支払方法を選択でき、新規注文のステータスは同様に「受付」です。

管理者による支払方法の変更は、ステータスが「受付」の間のみ可能です。

### 注文ステータスと進行ルール

| ステータス | 保存値 | 意味 |
| --- | --- | --- |
| 受付 | `received` | 注文受付後、送料・手数料や内容を確認する段階 |
| 入金待ち | `awaiting_payment` | 銀行振込の入金を待つ段階 |
| 発送準備中 | `preparing` | 発送に向けた準備を進める段階 |
| 発送済 | `shipped` | 出荷処理を完了した段階 |
| キャンセル | `cancelled` | キャンセルされた注文 |

支払方法ごとの通常の進行は以下のとおりです。

- **代金引換：** 受付 → 発送準備中 → 発送済
- **銀行振込：** 受付 → 入金待ち → 発送準備中 → 発送済
- **キャンセル：** 発送済みになる前の注文は管理者がキャンセル可能

送料・代引手数料の確定など、各段階で必要な条件を満たさなければ次のステータスへ進めません。

特に「発送準備中」から「発送済」へ進めるには、**配送個口が1件以上登録され、すべての個口に送り状番号が入力されていること**が必要です。

### 注文情報の編集制限

| 注文ステータス | 注文内容の編集 |
| --- | --- |
| 受付 | 編集可能 |
| 入金待ち | 警告を表示したうえで編集可能 |
| 発送準備中 | 警告を表示したうえで編集可能 |
| 発送済 | 編集不可 |
| キャンセル | 編集不可 |

注文内容には、注文明細や注文者・お届け先、送料・手数料などが含まれます。管理メモは注文ステータスにかかわらず編集できます。

配送・送り状情報は別の運用ルールとし、**発送済みでも修正可能**です。キャンセル済み注文では編集できません。

### 送料・代引手数料と注文金額

注文金額は、商品代金と送料・手数料を分けて管理します。

- `orders.total_amount`：商品代金の合計（送料・手数料は含めない）
- `orders.shipping_fee`：注文単位の送料。複数個口の場合も合算額を登録
- `orders.cod_fee`：代引手数料。銀行振込の場合は0円
- **最終的なお支払い総額：** 商品代金合計 ＋ 送料 ＋（代金引換の場合は代引手数料）

送料・代引手数料は管理者が手動で設定します。各金額は `null` を「未確定」、`0` を「確定済み・無料」として区別します。

購入者向けの注文確認画面では、送料・該当する手数料が注文受付後に加算されることを案内し、注文確定前にチェックボックスで同意を取得します。

購入者向けの注文詳細画面では、必要な金額が確定するまで支払総額を「未確定」と表示します。

### 配送・送り状情報

配送会社は現時点では**ヤマト運輸のみ**を想定しています。

- 注文に紐づく配送個口を `order_shippings` テーブルで管理
- 1注文に複数の個口を登録可能
- 個口ごとに送り状番号（`tracking_number`）を保存
- 管理画面で個口・送り状番号の追加、変更、削除が可能
- 発送済みの注文は、会員向け注文詳細画面に個口ごとの送り状番号と配送状況の確認リンクを表示

現時点では送り状番号を管理者が入力する方式です。ヤマト運輸B2クラウドとのCSV連携は未実装です。

### 注文時の備考欄と管理メモ

購入者は注文時に、包装・梱包方法、お届け日時、複数箱への分割などの希望を**任意の備考欄**に入力できます。

- `orders.customer_note` に保存（任意、最大1,000文字）
- 注文内容確認画面、注文完了画面、会員向け注文詳細画面に表示
- 管理画面の注文詳細では、注文商品の近くに強調表示
- 注文確定後は、購入者・管理者ともに備考欄を編集できない
- 顧客の希望が必ず実現できることを保証するものではない

一方、`orders.memo` は管理者が社内の対応状況などを記録するための**管理メモ**であり、顧客の備考とは別に扱います。

### 注文受付経路

| 受付経路 | 保存値 |
| --- | --- |
| Web | `web` |
| 電話 | `phone` |
| FAX | `fax` |
| 店頭 | `store` |
| その他 | `other` |

これらの定義は `app/Enums` にまとめています。Enumのケース名は大文字のスネークケースに統一しています。

### 入力文字数

フロントエンドの `maxlength` とサーバー側のバリデーションで、以下の上限を設定しています。

| 項目 | 最大文字数 |
| --- | --- |
| 郵便番号（`postal_code`） | 8 |
| 電話番号（`phone`） | 20 |
| 氏名（`name`） | 255 |
| 住所（`address`） | 255 |
| メールアドレス（`email`） | 255 |
| 注文時の備考（`customer_note`） | 1,000 |
| 送り状番号（`tracking_number`） | 20 |

注文者情報には `orderer_`、お届け先情報には `shipping_` のプレフィックスを付けています。

Web注文では注文者メールアドレスが必須ですが、管理画面での注文登録・顧客情報編集では任意です。

### 注文データの保存

注文時の商品名・単価・数量・小計は、注文明細に保存します。

注文者・お届け先・顧客の備考も注文ごとに保存するため、会員プロフィールとは別に管理します。

これにより、会員情報や商品マスタを後から変更しても、注文時点の情報を保持できます。

注文と明細の登録・更新、および配送情報の更新には、データベーストランザクションを使用しています。

## 現時点の対応範囲と今後の課題

本アプリケーションは学習・試作段階であり、以下の機能や運用対応は未実装、または今後の改善対象としています。

| 項目 | 現状 |
| --- | --- |
| 送料・代引手数料 | 注文単位の手動設定に対応。自動計算は未実装 |
| 配送・送り状管理 | 複数個口と追跡番号の管理に対応。B2クラウドCSV連携は未実装 |
| 外部決済連携 | 未実装。支払方法の記録のみ対応 |
| 入金の自動確認 | 未実装。管理者が確認してステータスを進行 |
| 在庫管理・在庫引当 | 未実装 |
| 注文確認・発送通知メール | 未実装。公開時にメール通知を整備予定 |
| メールアドレス認証 | 画面・ルートはあるが、現在は認証を必須としていない |
| パスワード再設定メール | 開発環境の `MAIL_MAILER=log` ではログに出力 |
| 自動テスト | テストケース未作成 |
| 店舗情報・案内ページ | 一部仮置き |

本番運用に向けては、メール送信設定、店舗情報・案内ページの整備、入力値の正規化、セキュリティ対策、テストの追加などを進める予定です。

## 制作について

本プロジェクトは、Laravelの学習を通じて習得した知識を活用し、実際の店舗運用を想定して制作したアプリケーションです。

基本的なCRUD処理や認証機能に加え、ゲスト・会員それぞれのカート管理、注文データの設計、管理者と会員の権限制御、送料・手数料の確定フロー、複数個口の配送管理、実務を想定した管理機能、レスポンシブ対応などに取り組みました。

現時点では学習・開発用のプロジェクトであり、本番運用に必要な機能や設定は今後整備する予定です。
