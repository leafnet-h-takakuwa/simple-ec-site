# Simple EC Site — 高桑商店

魚卵や海産物などの食品を扱う「高桑商店」を題材に制作した、Laravel製のECサイトです。

商品閲覧からカート・注文までの購入機能と、商品・注文・会員情報を扱う管理画面を備えています。

Web注文に加え、電話・FAX・店頭などで受け付けた注文も管理画面から登録できるようにし、小規模店舗での実際の運用を意識して開発しました。

現在は学習・試作段階であり、送料計算や在庫管理、メール通知など、一部の機能は未実装です。

## 制作の背景と目的

親族が運営する鮮魚・海産物販売サイトのリニューアルを想定して制作しました。

既存サイトは静的HTMLやPHPを中心とした構成で、商品情報の更新や注文管理などに改善の余地がありました。

そこで、Laravelとデータベースを利用し、商品情報や注文情報を一元管理できる仕組みを目指しました。

また、実際の店舗では高齢のお客様の利用も想定されるため、一般的なECサイトの機能を取り入れながらも、複雑な操作を避け、分かりやすい購入フローを意識しています。

### 開発で重視したこと

**1. 会員登録を必須にしない購入体験**

会員登録が購入の障壁にならないよう、ゲスト購入に対応しています。

一方、会員には住所・連絡先の保存や注文履歴の確認など、継続利用に便利な機能を用意しました。

**2. 自宅用・贈答用の両方に対応**

注文者とお届け先を分けて管理し、別住所への配送にも対応しています。

お届け先の指定に応じて、代金引換と銀行振込を使い分ける購入フローを採用しています。

**3. 注文時点の情報を保持**

会員情報や商品情報が後から変更されても、過去の注文内容が変わらないよう、注文者情報・配送先情報・商品名・単価などを注文データに保存しています。

**4. 店舗側の運用負担を軽減**

Web以外の受付経路にも対応し、管理画面から注文登録・内容修正・ステータス管理ができるようにしています。

**5. スマートフォンでも利用しやすい画面**

購入者向け画面だけでなく、管理画面もレスポンシブ対応しています。

管理画面では、PC向けのテーブル表示とスマートフォン向けのカード表示を使い分けています。

## 主な機能

### 購入者向け

| 機能 | 内容 |
| --- | --- |
| トップページ | 人気商品・新着商品・カテゴリを表示 |
| 商品一覧・詳細 | カテゴリによる絞り込み、新着順の表示、商品情報の確認 |
| カート | 商品の追加・数量変更・削除。ゲストと会員の両方に対応 |
| 注文 | 注文者・お届け先の入力 → 内容確認 → 注文確定 |
| 別住所への配送 | 注文者と異なるお届け先を指定可能 |
| 会員登録・認証 | 登録、ログイン、ログアウト、パスワード再設定 |
| 会員情報 | 氏名・メールアドレス・郵便番号・住所・電話番号の編集 |
| 注文時の自動入力 | 登録済みの会員情報を注文フォームに初期表示 |
| 注文履歴 | ログイン中の会員自身の注文一覧・詳細を表示 |

#### カートの仕様

- ゲストカートはセッションで保持
- 会員カートはデータベースで保持
- 一般会員としてログインすると、ゲストカートの商品を会員カートに統合
- 購入者向けカートの数量は、1商品につき最大10個

#### 会員情報と注文情報

会員情報は注文フォームへの自動入力に利用しますが、注文時に入力した情報で会員プロフィールを更新することはありません。

注文情報は独立して保存されるため、会員情報を変更しても過去の注文には影響しません。

### 管理者向け

| 機能 | 内容 |
| --- | --- |
| ダッシュボード | 進行中・直近7日間・全件・発送済みの注文件数、商品の最終更新日時を表示 |
| 商品管理 | 一覧・検索・登録・編集・削除、画像の登録・変更・削除 |
| 商品の表示設定 | 公開／非公開、定番商品の設定 |
| 注文検索 | 注文番号・注文者氏名・注文日・ステータスによる絞り込み |
| 手動注文登録 | Web・電話・FAX・店頭・その他の受付経路を選択して登録 |
| 注文明細編集 | 商品・単価・数量の変更、明細の追加・削除、合計金額の再計算 |
| 自由入力の明細 | 商品マスタにない商品名・金額を入力して登録 |
| 注文情報の変更 | 注文者・お届け先・支払方法・ステータス・管理メモの更新 |
| 会員情報の閲覧 | 会員一覧・詳細、会員ごとの注文履歴を表示 |

管理画面はログイン認証と `is_admin` による権限確認で保護しています。

管理者アカウントは購入者向け注文画面からの注文を行えません。

会員情報は管理者による参照のみとし、編集機能は設けていません。顧客からの依頼による注文内容の変更は、会員プロフィールとは独立して管理します。

## ローカル環境のセットアップ

以下の手順は、PHP・Composer・Node.js・PostgreSQLを利用できる環境でのセットアップ例です。

コマンドはリポジトリ直下で実行します。

### 1. 必要な環境

- PHP 8.2以上と、Laravel・Composerの依存パッケージが要求するPHP拡張
- PostgreSQL接続用のPHP拡張（`pdo_pgsql`）
- Composer 2系
- Node.js 22系とnpm
- PostgreSQLと、接続可能なデータベース・ユーザー

**データベースについて**

`.env.example` の初期設定はSQLiteですが、本アプリケーションではPostgreSQLを前提としています。

商品名・注文者氏名の検索では `ILIKE`、商品の並び替えでは `NULLS LAST` を使用しています。

他のデータベースを利用する場合は、これらのSQLとマイグレーションの互換性を確認してください。

### 2. リポジトリの取得と依存パッケージのインストール

`<repository-url>` は実際のリポジトリURLに置き換えてください。

```bash
git clone <repository-url> simple-ec-site
cd simple-ec-site

cp .env.example .env

composer install
npm ci

php artisan key:generate
```

### 3. データベースと環境変数の設定

PostgreSQLに開発用データベースと接続ユーザーを用意し、`.env` を編集します。

以下は設定例です。接続先に合わせて変更してください。

```dotenv
APP_NAME="高桑商店"
APP_ENV=local
APP_DEBUG=true
APP_URL=http://localhost:8000

APP_LOCALE=ja
APP_FALLBACK_LOCALE=ja

DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=simple_ec_site
DB_USERNAME=simple_ec_user
DB_PASSWORD=your_local_password

SESSION_DRIVER=database
CACHE_STORE=database
QUEUE_CONNECTION=database
MAIL_MAILER=log
```

`APP_KEY` は `php artisan key:generate` で生成した値を使用します。

Docker環境で実行する場合は、PostgreSQLのホスト名やポート番号をコンテナ構成に合わせて設定してください。

セッション・キャッシュ・キュー用のテーブルは、アプリケーションのマイグレーションに含まれています。

### 4. テーブルとサンプルデータの作成

```bash
php artisan migrate --seed
php artisan storage:link
```

シーダーで作成するデータは次のとおりです。

- 管理者・一般会員のサンプルアカウント
- 商品12件（非公開商品を含む）
- 会員・ゲストの注文5件と、その注文明細

商品画像は初期データに含まれません。管理画面から登録できます。

画像は `storage/app/public/products` に保存し、`public/storage` 経由で表示します。

**注意：** `ProductSeeder` と `OrderSeeder` は実行のたびにデータを追加します。`php artisan db:seed` を繰り返すと商品・注文が重複するため、初回投入を前提に使用してください。

### 5. 開発サーバーの起動

```bash
composer run dev
```

Laravelの開発サーバー、キューワーカー、ログ表示、Viteをまとめて起動します。

起動後は http://localhost:8000 にアクセスしてください。

PHPサーバーとViteだけを個別に起動する場合は、別々のターミナルで実行します。

```bash
php artisan serve
```

```bash
npm run dev
```

## 注文・入力の仕様

### 支払方法

購入者向けWeb注文では、お届け先の指定に応じて支払方法を決定します。

| お届け先 | 支払方法 | 注文確定時のステータス |
| --- | --- | --- |
| 注文者と同じ | 代金引換（`cod`） | 受付（`received`） |
| 注文者と異なる | 銀行振込（`bank_transfer`） | 入金待ち（`awaiting_payment`） |

管理画面からの手動登録では支払方法を選択でき、新規注文のステータスは「受付」です。

登録後も管理画面から支払方法とステータスを変更できます。

### 注文ステータス

| ステータス | 保存値 |
| --- | --- |
| 受付 | `received` |
| 入金待ち | `awaiting_payment` |
| 発送準備中 | `preparing` |
| 発送済 | `shipped` |

### 注文受付経路

| 受付経路 | 保存値 |
| --- | --- |
| Web | `web` |
| 電話 | `phone` |
| FAX | `fax` |
| 店頭 | `store` |
| その他 | `other` |

これらの定義は `app/Enums` にまとめています。

### 入力文字数

フロントエンドの `maxlength` とサーバー側のバリデーションで、以下の上限を設定しています。

| 項目 | 最大文字数 |
| --- | --- |
| 郵便番号（`postal_code`） | 8 |
| 電話番号（`phone`） | 20 |
| 氏名（`name`） | 255 |
| 住所（`address`） | 255 |
| メールアドレス（`email`） | 255 |

注文者情報には `orderer_`、お届け先情報には `shipping_` のプレフィックスを付けています。

Web注文では注文者メールアドレスが必須ですが、管理画面での注文登録・顧客情報編集では任意です。

### 注文データの保存

注文時の商品名・単価・数量・小計は、注文明細に保存します。

注文者・お届け先も注文ごとに保存するため、会員プロフィールとは別に管理します。

これにより、会員情報や商品マスタを後から変更しても、注文時点の情報を保持できます。

注文と明細の登録・更新には、データベーストランザクションを使用しています。

## ディレクトリ構成

```text
app/
├── Enums/                 # 商品カテゴリ・受付経路・注文状態・支払方法
├── Http/
│   ├── Controllers/       # 購入者向け処理
│   │   └── Admin/         # 管理者向け処理
│   └── Middleware/        # 管理者権限の確認
├── Listeners/             # ログイン時のカート統合
└── Models/                # 会員・商品・カート・注文・明細

database/
├── factories/             # モデル用のサンプルデータ定義
├── migrations/            # テーブル定義・変更履歴
└── seeders/               # 初期データ

resources/
├── css/                   # スタイル
├── js/                    # JavaScript
└── views/
    ├── admin/             # 管理画面
    ├── carts/             # カート
    ├── livewire/auth/     # 認証画面
    ├── orders/            # 注文画面
    ├── products/          # 商品画面
    └── profile/           # 会員情報編集

routes/
├── web.php                # 購入者・管理者向けルート
└── auth.php               # 認証ルート
```
